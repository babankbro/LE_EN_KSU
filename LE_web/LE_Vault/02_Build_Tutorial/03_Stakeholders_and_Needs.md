## ข้อมูลจริงของหลักสูตรนี้

**ผู้มีส่วนได้ส่วนเสียและแหล่งหลักฐาน** (ภาคผนวก ง §2 · [[appendices_A_to_D]])

| รหัสที่ใช้ในระบบ | กลุ่ม | ประเภท |
|---|---|---|
| SH1–SH4 | ศิษย์เก่า · ผู้ปกครอง · ผู้ใช้บัณฑิต · นักศึกษาปัจจุบัน | เสียงตรง (verbatim) |
| EV1 | Thailand NQF ระดับ 6 · มาตรฐานคุณวุฒิ 2565 · Washington Accord · ABET · QAA Engineering | มาตรฐาน/กรอบสมรรถนะ |
| EV2 | ทักษะกำลังคนเกษตรสมัยใหม่ · TPQI · ESCO · O*NET · ประกาศงาน Jobsdb | ข้อมูลอาชีพและตลาดแรงงาน |
| EV3 | ยุทธศาสตร์และแผนของประเทศ · วิสัยทัศน์ พันธกิจ อัตลักษณ์ของมหาวิทยาลัย | นโยบายและสถาบัน |

เล่มและภาคผนวก ง **ไม่ระบุวิธีเก็บข้อมูล ขนาดตัวอย่าง และช่วงเวลา** ของทั้ง 4 กลุ่ม (ISS-25)

**ความต้องการ 14 ข้อ** (ภาคผนวก ง §6–8) และ PLO ที่ตอบ

| N | ความต้องการ | ลำดับ | PLO |
|---|---|:-:|---|
| N01 | ความรู้พื้นฐานคณิตศาสตร์ วิทยาศาสตร์ และวิศวกรรม | P0 | LE1 |
| N02 | การคิดวิเคราะห์และแก้ปัญหาซับซ้อน | P0 | LE1 |
| N03 | ออกแบบระบบและกระบวนการ | P0 | IE1 · SC1 |
| N04 | สืบค้น วิเคราะห์ข้อมูล และตรวจสอบผล | P0 | IE2 · SC3 |
| N05 | เทคโนโลยีดิจิทัลและเครื่องมือสมัยใหม่ | P1 | IE3 · SC3 |
| N06 | บริหารขนส่ง คลังสินค้า และโซ่อุปทาน | P1 | SC1 · SC2 |
| N07 | ประสิทธิภาพ ต้นทุน เวลา และคุณภาพ | P1 | IE1 · IE4 · SC1 · SC2 |
| N08 | กฎหมาย จริยธรรม และความปลอดภัย | P0 | LE2 |
| N09 | ผลกระทบทางเศรษฐกิจ สังคม สิ่งแวดล้อม | P0 | LE2 · IE1 · SC4 |
| N10 | การสื่อสารไทย–อังกฤษในงานวิชาชีพ | P0 | LE3 |
| N11 | การทำงานร่วมกับผู้อื่นและการบริหารงาน | P0 | LE3 · IE4 |
| N12 | การเรียนรู้ด้วยตนเองและปรับตัว | P0 | LE4 |
| N13 | นวัตกรรมหรือแนวทางปรับปรุงที่ใช้ได้จริง | P2 | IE5 · SC4 |
| N14 | การประยุกต์วิศวกรรมกับเศรษฐกิจและพื้นที่ | P2 | IE5 · SC4 |

- P0 = 9 ข้อ · P1 = 3 ข้อ · P2 = 2 ข้อ · ส่วน P3 (Excel, Power BI, WMS, TMS, GIS, Barcode ฯลฯ) ภาคผนวกจัดไว้ในกิจกรรมและ CLO ไม่ใช่ PLO
- **N03, N09, N14 ไม่มีเสียงตรงจากผู้มีส่วนได้ส่วนเสีย** อาศัยมาตรฐานหรือข้อมูลสถาบันเท่านั้น
- เมื่อแยกวิชาเอก **N06 มีเพียง SC1 และ SC2 รองรับ** นักศึกษา IE จึงไม่มี PLO ใดตอบ N06 ส่วน SC ครอบคลุมครบ 14 ข้อ

**จาก curriculum.json:** `plos[].needs` เป็นข้อความความต้องการจากตารางที่ 1 ของข้อ 3.3 รวม 28 ข้อความ (ไม่มีรหัส N) · `plos[].sources` เป็นชื่อกลุ่มแบบข้อความอิสระ · `plos[].policy.plans` มี 10 รายการไม่ซ้ำ ซึ่งมาจากเอกสาร 8 ฉบับ (ยุทธศาสตร์ชาติ 2 ยุทธศาสตร์ และแผนฯ ฉบับที่ 13 สองหมุดหมาย นับเป็นฉบับละหนึ่ง)

## Prompt A · วอลต์

```text
ภาคผนวก ง อยู่ใน PDF แยก ตัวดึงยังไม่อ่าน จึงกรอกเป็นข้อมูลเสริมในวอลต์ (ราก = LE_web/)

1. สร้าง LE_Vault/overrides/supplement_stakeholders.md
   ตาราง: id | กลุ่ม | ประเภท (direct|standard|occupational|policy) | วิธีเก็บข้อมูล | ขนาดตัวอย่าง | ช่วงเวลา | source
   แถว SH1–SH4 และ EV1–EV3 ตามภาคผนวก ง §2
   ช่องวิธีเก็บ ขนาดตัวอย่าง ช่วงเวลา ให้เขียน "ไม่ระบุในเล่ม" ห้ามใส่ตัวเลขที่ไม่มีหลักฐาน
2. สร้าง LE_Vault/overrides/supplement_needs.md
   ตาราง: id | ความต้องการ | ลำดับ (P0|P1|P2) | หลักฐาน (direct|document-only) | plos | source
   แถว N01–N14 ตามภาคผนวก ง §6–8 · plos เป็นรายการคั่นด้วย , เช่น PLO_IE1, PLO_SC1
   source ทุกแถว = "ภาคผนวก ง §6–8"
   ปิดท้ายไฟล์ด้วยรายการ P3 (เครื่องมือ) และกิจกรรมที่ภาคผนวก ง §9 ส่งไปให้
3. ขยาย tools/build_vault.py

     แต่ละโน้ตลิงก์ไป [[PLO_...]] และแสดงว่ามีเสียงตรงหรือเป็นเอกสารอย่างเดียว
   - เติมหัวข้อ "ตอบความต้องการ" ในโน้ต PLO ด้วย [[N0x]]
   - เขียน LE_Vault/10_Curriculum/00_OBE_Trace.md

     ปิดท้ายด้วย "ความต้องการที่ไม่มี PLO ของวิชาเอกนั้นตอบ" และ "PLO ที่ไม่ตอบความต้องการใด"
     ตารางนโยบาย: เอกสาร | PLO ที่อ้าง (จาก plos[].policy.plans จัดกลุ่มตามชื่อเอกสารก่อนเครื่องหมาย :)
4. throw error ถ้าอ่าน needs ได้ 0 แถว หรือ plos ในแถวใดอ้าง PLO ที่ไม่มีใน curriculum.json
5. พิมพ์: จำนวน SH/EV · จำนวน N ต่อ P0/P1/P2 · จำนวน N ที่ไม่มีเสียงตรง · ช่องว่างต่อวิชาเอก
```

## Prompt B · เว็บ

```text
1. ขยาย web/scripts/build-data.mjs ให้อ่านไฟล์ LE_Vault/overrides/supplement_*.md
   ไฟล์ supplement ต้องมีคอลัมน์ source (แทน ISS) และไม่ถือเป็นการ override ค่าในเล่ม
   เขียน web/src/generated/needs.js
     STAKEHOLDERS = [{ id, name, kind, method, n, period, source }]
     NEEDS        = [{ id, text, priority, evidence, plos: [], source }]
     NEED_PLO     = { [needId]: [ploId] } · PLO_NEED = { [ploId]: [needId] }
   throw ถ้า NEEDS ว่าง หรือ plos อ้างรหัสที่ไม่มีใน PLOS
2. หน้า web/src/pages/Obe.jsx (/obe) ใช้ useMajor() ทุกส่วน
   ① id="sh"     ตารางผู้มีส่วนได้ส่วนเสีย แยก "เสียงตรง" กับ "หลักฐานเชิงเอกสาร"
                  ช่องที่เป็น "ไม่ระบุในเล่ม" ให้แสดง <WarnBadge kind="noSampleSize"/> (ISS-25)
   ② id="needs"  การ์ด N01–N14 สีตามลำดับ P0/P1/P2 · ป้าย "ไม่มีเสียงตรง" สำหรับ evidence=document-only
                  ป้าย PLO บนการ์ดกรองตามวิชาเอก (IE ซ่อน SC*, SC ซ่อน IE*)
   ③ id="plo-needs" เมทริกซ์ Need × PLO ของวิชาเอกที่เลือก (ALL = แสดงสองตาราง IE และ SC)
                  แถบตรวจด้านบน: N ที่ไม่มี PLO ของวิชาเอกนั้นตอบ · PLO ที่ไม่ตอบ N ใด · ไม่มีปัญหา = แถบเขียว
   ④ id="policy" ตารางเอกสารนโยบาย ↔ PLO และข้อความ contribution จาก PLOS[].policy
                  จัดกลุ่มตามชื่อเอกสาร (ข้อความก่อน ":") แล้วนับจำนวนเอกสารจากข้อมูล
   ⑤ id="flow"   โครงสายธาร Need → PLO → YLO → CLO ใช้ Alluvial.jsx ภายหลัง ตอนนี้แสดง "รอข้อมูลขั้นที่ 10"
3. แก้ sections ของ /obe ใน navConfig.js ให้ id ตรงกับ ①–⑤ ข้างบน เพื่อให้ Sidebar เลื่อนถูกจุด
4. เพิ่ม N01–N14 และ SH/EV เข้า codeInfo.js (ดึงจาก generated/needs.js ไม่เก็บซ้ำ)
5. (ลำดับ C) web/src/pages/References.jsx (/refs) แสดงรายการเอกสารนโยบายจากข้อ 2④
   เอกสารที่ไม่มีปี เช่น "แผนส่งเสริมเศรษฐกิจดิจิทัล / Digital Economy" ให้ติด <WarnBadge kind="noYear"/>
```

> [!important] แยก "เสียงจริง" ออกจาก "เอกสาร" ให้เห็นบนหน้าเว็บ
> ภาคผนวก ง เองตั้งใจแยกสองอย่างนี้ "เพื่อไม่ให้สับสนว่าเป็นผลสำรวจ" ถ้าเว็บแสดงทุกความต้องการด้วยสีเดียวกัน ผู้ประเมินจะเข้าใจว่า N03, N09, N14 มาจากการสำรวจ ซึ่งไม่จริง

## ตรวจรับ

- [ ] `npm run data` พิมพ์ `STAKEHOLDERS=7 NEEDS=14` และ P0/P1/P2 = 9/3/2
- [ ] `/obe#needs` แสดง 14 การ์ด และ N03, N09, N14 มีป้าย "ไม่มีเสียงตรง"
- [ ] ช่องขนาดตัวอย่างของ SH1–SH4 แสดงป้ายเตือน ไม่ใช่ตัวเลขและไม่ใช่ช่องว่าง
- [ ] `/obe?major=IE#plo-needs` แถบตรวจขึ้นว่า N06 ไม่มี PLO ของวิชาเอก IE รองรับ
- [ ] `/obe?major=SC#plo-needs` แถบตรวจเป็นสีเขียว (ครบ 14 ข้อ)
- [ ] ทุก PLO ทั้ง 13 ข้อตอบความต้องการอย่างน้อยหนึ่งข้อ
- [ ] ส่วนนโยบายแสดง 10 รายการจาก 8 เอกสาร โดยตัวเลขมาจากการนับ ไม่ได้พิมพ์ลงโค้ด
- [ ] ชี้ที่ป้าย `N07` ในหน้าใดก็ได้แล้ว tooltip ขึ้นข้อความเต็มและ PLO ที่ตอบ
- [ ] คลิกหัวข้อ ①–⑤ ใน Sidebar แล้วหน้าเลื่อนไปถูกส่วน

> [!warning] กับดักที่พบในเล่มนี้
> - **ไม่มีวิธีเก็บข้อมูล ขนาดตัวอย่าง และช่วงเวลา** ทั้งในหมวด 2 และภาคผนวก ง (ISS-25) ห้ามเติมตัวเลขสมมติ ให้แสดงป้ายเตือน
> - **ชื่อกลุ่มแหล่งข้อมูลไม่ตรงกันระหว่างส่วน** ตารางที่ 1 ของข้อ 3.3 ใช้คำกว้าง เช่น "มาตรฐานสมรรถนะทางวิศวกรรม" ส่วนข้อ 3.4 ระบุ ผู้ปกครอง, TPQI, ESCO, O*NET, Jobsdb, WA, ABET, QAA ซึ่งไม่อยู่ในตารางที่ 1 อย่ารวมสองชุดเป็นชุดเดียวโดยไม่บอกที่มา
> - **`plos[].sources` เป็นข้อความอิสระ** มีทั้ง "ผู้ใช้บัณฑิต", "ผู้ใช้บัณฑิตในภาคอุตสาหกรรม", "ผู้ใช้บัณฑิตด้าน โลจิสติกส์" (มีช่องว่างแทรก) ถ้าจะนับต่อกลุ่ม ให้จับด้วยคำขึ้นต้นหลัง normalise ช่องว่าง
> - **รหัส "N13" หลุดเข้ามาในตารางข้อ 3.4** พร้อมวลี "ที่มา: ความต้องการที่กลั่นกรองจากแหล่งข้อมูล" (ISS-46) เป็นร่องรอยร่าง ไม่ใช่ข้อมูลอีกชุด
> - **ถ้อยคำเชิงเงื่อนไขในตารางความสอดคล้อง** เช่น "(เมื่อมีงานหรือหลักฐานเชิงพื้นที่รองรับ)" ของ IE5 และ "โดยไม่อ้างผลกระทบเชิงพื้นที่ที่ยังไม่มีหลักฐาน" ของ IE2 ให้แสดงตามเล่ม อย่าตัดทิ้ง
> - **"แผนส่งเสริมเศรษฐกิจดิจิทัล / Digital Economy" ไม่มีชื่อทางการและปี** และไม่มีแผนระดับภาคหรือจังหวัดเลย แม้เล่มเน้นกาฬสินธุ์และโซ่อุปทานเกษตร
> - **ตาราง PLO ↔ วิสัยทัศน์ พันธกิจ อัตลักษณ์ (3.3 ข้อ 3) ยังไม่อยู่ใน curriculum.json** ถ้าต้องการแสดง ให้กรอกเป็นไฟล์ `supplement_` เพิ่ม หรือขยายตัวดึง
